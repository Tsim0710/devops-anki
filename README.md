# devops-anki

Карточки для подготовки к DevOps-собеседованиям. Источник правды — YAML
в `cards/`, сборка автоматическая через GitHub Actions.

**Тренажёр: https://tsim0710.github.io/devops-anki/** — выбрал тему и уровень,
дальше вопрос → ответ → знаю/не знаю. Без логина, с телефона, всегда последняя
версия.

Что уже покрыто — [`plans/README.md`](plans/README.md).
Спецификация проекта — [`CLAUDE.md`](CLAUDE.md).

---

## Как устроено

| Что | Где |
|---|---|
| Карты | `cards/<domain>/<subtopic>.yaml` |
| Разрешённые subtopic | `taxonomy.yaml` |
| Форма карты | `schema.json` |
| Реестр id (append-only) | `ids.lock` |
| Снапшоты конспектов | `sources/` |
| Шаблон тренажёра | `web/drill.html` |
| Сборка | `build.py` |
| Карты покрытия | `plans/`, генератор `tools/coverage.py` |

**Дек = `DevOps::<domain>`.** Вся остальная навигация — теги:
`topic::<subtopic>`, `difficulty::junior|middle|senior`,
`source::theory|interview|web|core`, `situational`, `unverified`, `deprecated`.

Деки не дробятся до subtopic сознательно: импорт `.apkg` не переносит уже
существующие карты в другой дек, поэтому дек-на-тему означал бы, что любое
переименование темы навсегда оставляет карту в старом деке.

## Локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python build.py --validate
```

```bash
.venv/bin/python build.py
```

```bash
.venv/bin/python -m pytest tests/ -q
```

Индекс существующих карт — читать **перед** генерацией новой темы, чтобы
не плодить дубли:

```bash
.venv/bin/python build.py --index k8s
```

Перегенерация карт покрытия после закрытия домена:

```bash
.venv/bin/python tools/coverage.py
```

## Две поверхности

**Тренажёр** — повседневная. `build.py` вшивает карты прямо в страницу тем же
рендерингом, что уходит в Anki, поэтому расхождений между поверхностями нет.
Прогресс (упрощённый Лейтнер: не знаю → в начало очереди, знаю → дальше)
лежит в localStorage браузера: свой на каждом устройстве.

**Anki** — для интервальных повторений. Тренажёр гоняет вопросы, Anki помнит,
когда к ним вернуться.

Порядок импорта:

1. Пушнуть тег `vN` → CI кладёт `devops.apkg` в релиз.
2. **Синк AnkiWeb.**
3. Импорт `.apkg`.
4. **Синк AnkiWeb ещё раз.**

Пункты 2 и 4 не опциональны: импорт на несинхронизированной коллекции даёт
«one-way sync required» и теряет накопленное на другой стороне.

```bash
git tag v2 && git push origin v2
```

Тема и уровень в Anki задаются filtered deck:

```
deck:DevOps::k8s tag:topic::probes tag:difficulty::middle -tag:deprecated
```

**Рычаг перегрузки.** Если повторений становится слишком много — в браузере карт
выбрать `tag:difficulty::senior` → Suspend. Колода сжимается почти вдвое, прогресс
не теряется, перед собесом возвращается. Саспенд переживает импорт, но **новые
карты приезжают активными** — после крупной генерации пересаспендить.

## Правила, которые легко нарушить

- `id` карты **вечен**. Из него считается GUID заметки — единственное, что
  связывает карту в репозитории с историей повторений. Сменил `id` → потерял
  прогресс. Переехала тема — меняется поле `subtopic`, `id` остаётся старым.
- **Удаления через YAML не существует.** `.apkg` аддитивен: убранная из YAML
  карта остаётся на устройстве. Вывод из оборота — `deprecated: true`,
  потом ручная чистка `tag:deprecated` в Anki.
- Многострочные поля — только `|`. `>` склеивает строки и ломает отступы в коде.
- `verified: false` по умолчанию. Флаг снимает только человек, после вычитки.
- `plans/*.md` не правятся руками — они генерируются.
